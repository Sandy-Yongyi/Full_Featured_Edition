# 第三模式 PLC 报文

## 配置与代码边界

`ModeConfig.toml` 只选择采数和运动策略，当前项目设置 `strategy_name = 3`。
`MovingFrameData.py` 由项目固定定义22轴报文，不判断模式；对外提供
`SendMovingFrameData`、`ReceiveMovingFrameData`、`AxisData` 和 `create_axis_list`。

本轮对 `PlcCommon.py` 和 `PlcFrame.py` 的修改已撤回，两个文件与原始版本一致。
底层固定导入同名接收类，通过字段注解解析数据，不判断模式。
后续项目只需在 `MovingFrameData.py` 修改项目字段、轴数及长度。
轴数常量供数组创建、Repeat解析数量和帧长度共同使用；设备轴映射另按设备合同适配。

## 公共约定与查询

- 大端序；帧头 `02 02 02 02`，帧尾 `03 03 03 03`。
- 三种模式查询均为 `02 02 02 02 01 03 03 03 03`，共9字节。
- 查询中的 `01` 是单字节指令，不使用运动帧的 int16 Type 字段，不附带清零载荷。
- 第三模式运动和接收载荷中的全部字段为 int16，每项2字节。
- 每个轴按 `Pos → Speed → Status` 排列，连续22组；顺序已记录在 `MachineAxisMap.py`。

## 第三模式 PC 发送运动帧

| 字段 | 载荷字节偏移 | 说明 |
|---|---:|---|
| Type | 0 | 默认2，运动数据帧 |
| Status | 2 | 公共状态位 |
| Operate | 4 | 总使能及设备开关 |
| HeartBeat | 6 | 心跳 |
| AxisList | 8 | 22 × 3 × 2 = 132字节 |

载荷140字节，含帧头帧尾共148字节。

Status 位：bit0=伺服正常，bit1=激光位可放行，bit2=手补位可放行，bit3=喷涂位可放行。
每位0表示条件不成立，1表示成立。

## 第三模式 PC 接收

| 字段 | 载荷字节偏移 | 说明 |
|---|---:|---|
| Status | 0 | 公共状态位 |
| Operate | 2 | 总使能及设备开关 |
| HeartBeat | 4 | 心跳 |
| AxisList | 6 | 22 × 3 × 2 = 132字节 |

载荷138字节，含帧头帧尾共146字节；无 Type、ChainPulse、ChainSpeed。

Status 位：bit0=伺服正常，bit1=到达激光位，bit2=激光位放行完成，
bit3=到达手补位，bit4=手补位放行完成，bit5=到达喷涂位，bit6=喷涂位放行完成。
每位0表示条件不成立，1表示成立。

## 第三模式收发共用 Operate

| 位 | 1的含义（0为关闭） |
|---|---|
| bit0 | 开启总使能 |
| bit1 | 开启左边侧面喷涂机 |
| bit2 | 开启左边二维往复机 |
| bit3 | 开启右边侧面喷涂机 |
| bit4 | 开启右边二维往复机 |

## 当前接入与验证范围

第三模式主循环发送9字节查询，根据反馈驱动索引18～21的四个激光轴。
启动回零、到位扫描、速度保存和脉冲合成见《第三模式激光扫描.md》。
模式1/2业务分支保留，但本项目固定报文无ChainPulse，不代表可直接运行旧项目链条规划。
已核对两个底层文件相对原始版本无差异。未连接PLC或执行实机运动调试。
底层接收仍沿用原有帧头帧尾判断，未保留此前新增的固定长度分包、粘包处理。
